# 모바일·태블릿 UI 정렬과 작업을 유지하는 화면잠금

부모가 사용자에게 전달한 승인 계획을 구현 기록으로 보존한다. 기준 main은 `39be49a`다. 현재 단계는 격리 worktree의 구현과 로컬 검증이며 **부모의 실제 QA 통과 확인 전 문서도 포함해 커밋·푸시·배포하지 않는다.** 저장된 모델·fast·tier 설정은 변경하지 않는다.

## 확정 범위

- 모바일·태블릿 우선. 단계와 본문은 독립 행을 유지하며 동일한 3개 track과 gap을 쓴다. 준비·전사 실행·메모 정리 1:2, 전사 검토 2:1. 모바일의 한 줄 단계·완료 상세·키보드 초점 보호를 유지한다.
- 자동 화면잠금: 60/180/300/600/1800/3600초/사용 안 함, 기본 60초. 초단위 상시 표시. 실제 앱 사용자 입력·터치·키보드·스크롤로 갱신하며 작업 진행·네트워크는 활동이 아니다. 복귀 시 만료부터 검사한다.
- 기본 `표준 · 작업 이어가기`의 자동·수동 화면잠금은 민감 DOM/접근성 트리와 새 명령을 차단하며 승인한 녹음·준비·STT·정리는 계속한다. `엄격 · 잠글 때 작업 중지`는 잠금 또는 visibility hidden에서 기존 전체 잠금의 완료분 보존·중단 경로를 쓴다. 정책 변경은 다음 경계부터 적용한다. blur 자체와 복귀는 사용자 활동/엄격 잠금 경계가 아니다. 별도 ‘작업 중단하고 완전히 잠그기’는 두 모드에서 명시 확인 후 작동한다.
- 화면잠금 중 마지막 작업과 암호화 저장이 끝나면 키·민감 참조를 해제한다. 작업이 없으면 바로 보존 후 해제한다. 화면 복귀·필요한 미저장 편집은 기존 암호화 경로로 보존한다. 미저장 API 키 원문은 복원 상태에 복사하지 않는다.
- 살아 있는 작업의 화면 재인증은 기존 unlock/restore와 분리한다. 실패·늦은 재인증이 job/owner를 훼손하지 않도록 한다. 기존 전체 잠금의 저장 실패·늦은 응답·한 탭 소유권 보호를 유지한다.
- 앱 관리 저장은 암호화한다. 새 비밀·암호·검증값의 영구 저장을 추가하지 않는다. 브라우저 Blob 디스크 사용·OS 메모리·개발자 도구 보호를 암호화 저장과 혼동하지 않는다.

## 검사 범위

각 변경은 필요한 실패 검사부터 작성하고 해당 검사만 통과시킨다. 재사용 가능한 동일 코드의 passing evidence는 반복하지 않는다. 기본 대상은 vault/screen state, idle, controller/recording의 잠금 경계, UI 초안, provider transport와 responsive geometry다. 마지막에 앱 타입/빌드·공개 산출물과 변경 흐름의 통합 브라우저 검사를 한 번 묶는다. 전체 suite는 추가 요청 없이 실행하지 않는다.

화면 폭은 360/390/768/820/1024/1180/1440px와 실제 변경한 breakpoint 양쪽을 확인한다. 한글/영문, 빈 상태·파일/준비·실행 중·오류·편집·설정/모달·잠금/복귀를 변경 영향에 맞춰 고른다. 에뮬레이션은 실제 휴대폰 suspend/키보드/마이크 검증과 구분한다.

저장 감사는 합성 sentinel만 사용해 IndexedDB의 문자열/바이너리 원시값, Web Storage, CacheStorage, SW, 콘솔, 잠긴 DOM/AX, 정상 재인증 복구를 확인한다. HTTP 캐시와 Blob 수명도 구분해 기록한다. trace/HAR/캡처에 실키나 실회의 자료를 넣지 않는다. 배포 후에는 운영 원점에서 별도 합성 감사가 필요하다.
