# 공통 화면 컨테이너 폭

2026-10-29 사용자는 처리 기록·설정·음성 메모 화면의 컨테이너 폭을 하나로 통일하도록 요청했다. 공통 `.main-content`는 최대 1100px인데 설정만 내부에서 960px로 제한하고 있었다. 설정의 별도 폭 제한을 제거해 세 화면이 공통 컨테이너를 따르게 했다. 내부 카드 비율과 기존 1100px 반응형 경계는 유지한다.

세로 스크롤이 있을 때만 화면이 15px 좁아지는 차이도 브라우저에서 재현했다. 데스크톱 스크롤 영역 `.main`에 `scrollbar-gutter: stable`을 적용하고, 문서가 스크롤되는 1100px 이하에서는 앱 화면이 있는 HTML 루트에 같은 설정을 적용한다. 보관함 잠금·생성 화면은 이 루트 선택자에 포함하지 않는다. 스크롤바 유무와 관계없이 화면을 오갈 때 좌우 경계를 보존한다.

## 실제 로컬 화면 검증

별도 Chrome 창에서 실제 App·Home·History·Settings 컴포넌트에 빈 합성 목록을 제공해 확인했다. 제공사·보관함·키 저장 경로는 연결하지 않았다. 각 화면의 제목을 포함하는 바깥 컨테이너와 `.main-content`의 좌우 경계를 읽고, 같은 뷰포트의 세 화면 간 경계 차이가 1px 이하이며 가로 넘침이 없는지 검사했다.

| 뷰포트 | 처리 기록 | 설정 | 음성 메모 | 결과 |
| --- | --- | --- | --- | --- |
| 1610×1068 | 1100px | 1100px | 1100px | 동일한 좌우 경계·넘침 없음 |
| 1100×900 | 1045px | 1045px | 1045px | 동일한 좌우 경계·넘침 없음 |
| 360×800 | 313px | 313px | 313px | 동일한 좌우 경계·넘침 없음 |

실측값은 Chrome이 확보한 스크롤바 공간을 포함한 결과이며 운영체제의 오버레이 스크롤바 설정에 따라 사용 가능한 폭은 달라질 수 있다. 고정된 모바일 픽셀 폭을 새로 지정하지 않는다. [실측 JSON](geometry.json)에 변경 전 설정 960px와 최종 9개 측정값이 있다. 임시 뷰포트는 기본값으로 복원했고 임시 HTML/TSX와 탭은 제거했다.

## 검사 명령과 범위

CSS 변경이므로 기존 동작을 반복하는 단위 테스트를 추가하거나 전체 테스트를 실행하지 않았다. 위 브라우저 경계 검사와 최종 산출물 검사로 범위를 제한했다.

```sh
WRANGLER_LOG_PATH=/private/tmp/mom-shared-container-build.log npx vite build
# 통과. 기존 미디어 정적·동적 import 혼용 및 큰 chunk 경고 유지.
npm run test:secret
# 앱 소스·정적 자산·최종 클라이언트 산출물 검사 통과.
git diff --check
# 통과.
```

JSON에 저장된 9개 측정값도 Python으로 재검사했다. 뷰포트마다 세 화면이 모두 포함되고, 본문과 화면 경계가 같으며 화면 간 좌우 경계 차이가 1px 이하·가로 넘침 없음이 모두 통과했다. 디자인 원본 6개 파일의 SHA-256과 새 문서의 로컬 링크도 확인했다.

변경 파일은 `src/react-app/ui/styles.css`, `src/react-app/ui/mobile-navigation.css`, `docs/README.md`와 이 검증 기록·실측 JSON·화면 6개다. 앞선 작업 트리 변경은 보존했다. 실제 사용자 데이터·키·선택 모델은 변경하지 않았다. 채워진 장문 목록, 개별 전사·정리 작업 상태, 다른 브라우저 엔진, 실제 제공사 요청과 배포는 이번 범위에서 확인하지 않았다. 로컬 서버는 계속 실행하며 커밋·푸시·배포는 하지 않았다.
