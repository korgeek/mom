# 로컬 보관함 보안 점검 초안 · 2026-10-29

대상은 현재 작업 트리의 소스와 합성 테스트다. 실제 사용자 IndexedDB, 비밀 파일, 자격증명과 회의 데이터는 열거나 전송하지 않았다. 이 기록은 배포 승인이나 완전한 보안 보증이 아니다.

## 확인된 위험

1. **상황 의존 · 잘못된 암호와 wrappedKey 손상의 구별 불가.** 정상 형태의 wrappedKey, salt 또는 IV가 손상되면 올바른 암호에도 AES-GCM 인증 `OperationError`가 나며 실패로 집계된다. 5회 반복 시 실제 암호가 맞아도 삭제될 수 있다. 신뢰할 별도 검증자 없이 이 두 원인은 구별할 수 없으므로 이 데이터 손실 조건을 사용자에게 명확히 설명해야 한다. 합성 손상 테스트에서 5회 삭제 경로를 확인했다.
2. **해결 확인 · 삭제 실패 후 다른 탭의 새 보관함 보호.** 최초 검토에서 발견한 stale retry 위험에 대해, 재시도는 원래 vault ID를 유지하고 `clearVaultDatabase`의 동일 read-write transaction에서 현재 header의 vault ID와 실패 5회·삭제 대기 latch를 확인한 뒤에만 삭제한다. 소스 검토와 합성 다른 탭 교체 테스트에서 기존 재시도가 새 vault를 지우지 않는 것을 확인했다. 실제 사용자 데이터로 검증하지 않았다.
3. **해결 확인 · 실패 정책 입력 경계.** 짧거나 숫자 전용인 잘못된 암호도 이제 인증 실패로 집계된다. 256 코드포인트나 1024 UTF-8 바이트를 초과한 입력, 저장소 오류와 취소는 별도 오류로 처리한다. 기존 8자 암호 호환은 유지된다.
4. **중간 · 약한 암호의 오프라인 추측.** 신규 생성은 15–256자로 상향하고 일부 반복·흔한 암호를 제한하지만, 길이만으로 추측 저항이 보장되지는 않는다. 기존 8자 암호는 호환을 위해 유지된다. 탈취한 DB의 공개 salt·wrappedKey로 앱 밖에서 후보를 시험할 수 있으므로 3/5 정책은 복사본에 적용되지 않는다. PBKDF2-SHA256 600,000회는 추측 비용을 높인다. 긴 고유 암호를 권고해야 한다. 카운터도 공개 IndexedDB에 있으므로 DB를 수정할 수 있는 공격자의 롤백을 막지 못한다.
5. **상황 의존 · 이전 DB 사본과 암호 변경.** UI에 노출되지 않은 재포장 API는 기존 데이터키를 새로운 salt/IV와 암호로 다시 감싼다. 이전 header와 이전 암호를 가진 공격자가 기존 데이터키를 복원하면 동일 keyId로 작성된 이후 레코드도 해독할 수 있다. 이 API는 탈취된 과거 사본의 권한 철회가 아니다. 철회에는 별도 데이터키 교체와 모든 레코드 재암호화가 필요하다.
6. **상황 의존 · 작업 중 화면 잠금과 완전 잠금의 차이.** 기본 `lockWorkPolicy: standard`에서 실행 중 `screenLock`은 UI를 가리지만 작업 완료 전까지 열린 보관함과 복호화 키를 유지한다. strict는 즉시 전체 잠금 경로를 호출한다. 이는 도난된 DB의 오프라인 공격과 구분되는, 잠금 중 실행 프로세스에 접근 가능한 공격자의 위험이다. UI는 이를 설명한다.

## 소스에서 확인한 경계

- `crypto.ts`는 16바이트 랜덤 salt, PBKDF2-SHA256, 256비트 데이터키, 12바이트 AES-GCM IV 및 128비트 태그를 사용한다. 레코드 AAD는 vault ID, record ID, key ID와 버전을 결합한다. `store.ts`는 암호화 전에 nonce를 IndexedDB transaction에서 예약하고 중복을 검사한다.
- `store.ts`는 카탈로그·프로젝트·음성 블록·자격증명 값을 암호화된 레코드로 쓰며, 세션 전용 키는 메모리 맵에 둔다. 공개 header, 레코드 ID, 암호문 크기와 nonce/operation 수 등은 암호화되지 않아 저장 규모와 활동량이 노출될 수 있다.
- 전체 잠금은 작업을 fence/cancel하고 세션 키 맵을 지우고 공개 UI 상태를 비운 뒤 저장 완료 시 데이터키 참조를 놓는다. 브라우저/JavaScript 런타임에서 메모리 완전 소거는 보장되지 않는다. 저장 실패 시 잠금 실패 상태로 처리하며 복구 경로를 남긴다.
- 모델 프로필 내보내기는 credential 참조·저장 키·테스트 결과를 제거한다. 네트워크 호출은 저장 origin을 확인하고 Authorization 헤더를 사용하며 redirect를 거부한다. 요청 기록에서 오디오는 바이트 수·형식만 저장하고 현재 호출 키를 마스킹한다. 일반 텍스트에 별도로 입력된 다른 비밀값까지 자동으로 완벽히 탐지한다는 보장은 없다.
- 공급사 요청은 외부 전송이며 로컬 암호화가 공급사 보관·로그를 제어하지 않는다. 브라우저 확장, 악성 동일 출처 스크립트, 잠금 해제된 기기/프로세스 접근은 도난된 암호문 사본만 가진 공격자보다 강한 위협이다.

`npx vitest run tests/vault-auth-policy.spec.ts tests/passphrase-policy.spec.ts tests/vault-auth-ui.spec.tsx` — 수정 후 3개 파일 10개 통과. 다른 탭의 새 보관함 보존, 정상형 암호문 손상 시 삭제, 짧은 암호 실패 집계를 포함한다.

실제 브라우저 프로필의 저장물, GPU 기반 암호 추측 비용, 타 기기 메모리 포렌식, 모든 다중 탭 경합, 모든 UI 상태, 제공사의 실제 처리·보관은 이번 점검에서 검증하지 않았다. 변경된 3/5회 삭제 정책의 수정은 위 합성 테스트와 소스 범위에서만 확인했다.
