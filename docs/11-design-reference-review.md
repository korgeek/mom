## 2026-10-21 Lucide 아이콘 통일

사용자 요청에 따라 메모 아이콘 24개, 홈의 기록·고정·수정·삭제, 모바일 메뉴, 재생·정지, 페이지 이동, 항목 순서와 접기 표시를 Lucide로 통일한다. 기존 아이콘 ID·색상·표시 이름과 버튼의 접근성 이름은 유지하며 저장 데이터는 변환하지 않는다. 브랜드 문자와 실제 음성 파형은 유지한다. [변경·별도 Chrome 화면·선별 검사와 한계](superpowers/evidence/2026-10-21-lucide-icons/README.md)에 기록했다.

## 2026-10-21 폭 정렬과 업로드 기본 탭

사용자 후속 요청에 따라 단계별 사용량 명세를 정리 결과 열 안에 두어 폭을 맞춘다. 보안·잠금의 저장소 관리는 왼쪽 카드 열에 넣고 제목을 다른 카드와 같은 14px/600으로 표시한다. 전사 화면의 300px 고정 열 덮어쓰기를 제거해 상단 세 단계 버튼과 같은 1:2 배치를 사용한다. 1100px 이하의 단일 열은 유지한다.

새 음성 메모의 입력 방식은 파일 업로드가 기본이다. 마이크는 명시적으로 선택하며, 진행·일시정지·중단 상태의 녹음 화면에 돌아올 때 기존 상태를 가리지 않는다. [변경 파일·실제 화면·검사 결과와 한계](superpowers/evidence/2026-10-21-layout-alignment/README.md)에 기록했다. 원본 레퍼런스는 변경하지 않았으며 이번 변경은 로컬 작업이다.

**2026-10-18 후속 승인:** 사용자가 모바일 단계 개선의 main 병합·커밋·푸시·배포를 요청했다. 원격 main `70ff273` 이후 변경이 없음을 fetch로 확인했으며 아래 로컬 완료본 `2fe1467`의 제품 코드·검증 결과를 재사용한다. 별도 합성 보관함의 운영 원점 확인과 실제 제공 자산 대조를 수행한 뒤 배포 결과를 보고한다. 이전의 로컬 전용 기록은 당시 범위로 보존한다.

## 2026-10-17 모바일 단계와 완료 상세

사용자의 배포 후 스크린샷에서 단계 버튼이 2+1줄로 표시되고 아이콘·색상이 첫 화면 대부분을 차지하는 것을 확인했다. 후속 요청에 따라 모바일의 기존 세 단계 버튼을 한 줄로 맞추고, 부가 꾸미기 선택만 요약 후 펼침으로 바꾼다. 단계 이동과 상세 펼침을 별도 세로 단계 목록으로 중복하지 않는다.

완료한 음성 준비·전사 실행 상세는 명시적인 다음 단계 이동이 실제 반영된 뒤 돌아올 때 접는다. 자동 완료 시 읽던 화면을 접지 않는다. 완료 표시·실제 저장 청크 수 등의 요약을 남기고 상세 버튼으로 다시 연다. 완료 원본/청크/전사 버전의 식별자에 묶인 잠금 해제 세션의 UI 상태이며, 결과 초기화나 새 작업에 과거 접힘을 적용하지 않는다. 미저장 입력·활성 요청·새 실패/결과 불명·누락/미확인 전사·초기화 편집은 상세를 펼친다. 상세 접기는 DOM의 입력을 재생성하지 않으며 선택 전사 검토와 최종 Markdown 결과·복사·다운로드를 감싸지 않는다. PC에서 새 접기 컨트롤을 숨기고 기존 배치를 유지한다. [실제 렌더링·선별 검사와 한계](superpowers/evidence/2026-10-17-mobile-stages/README.md)에 기록한다. 이번 후속 구현·검증은 로컬이며 원격 푸시·배포를 수행하지 않는다.

## 2026-10-17 처리 기록과 명시적 청크 초기화

사용자는 처리 기록·홈 목록과 청크 재준비의 앞선 제안을 함께 구현하도록 승인하고 서브 에이전트 사용을 허용했다. 추가로 사이드바 `모든 음성 메모 N개`는 정보 표시로 바꾸고 화살표/링크를 제거하도록 요청했다.

- 처리 기록은 처리 이력이 있는 메모를 최근 실제 처리 시각순으로 15개씩 보여준다. 메모 상세는 전체/STT/LLM 필터와 최신 호출순 15개 페이지를 제공한다. 실측 시각이 없는 과거 기록은 메모 수정일을 처리 시각으로 만들지 않고 저장 순서를 유지한다. 목록에는 실제 요청 수·최근 상태, 상세에는 알려진 모델/시간/사용량/비용/경로를 보인다. 미제공 행과 반복 설명을 제거한다.
- 홈은 미처리 메모를 포함한 전체 메모를 최근 수정순 15개씩 보여주고, 각 메모의 처리 기록으로 연결한다. 이름 변경/삭제/고정/기존 열기 동작은 유지한다. 브랜드와 최근 제목은 홈 이동이며 아래 전체 개수는 클릭되지 않는 정보다.
- 전사 청크 정보 옆 작은 연필은 음성 준비로 이동해 청크·압축을 펼치고 그 위치로 스크롤/키보드 초점을 옮긴다. 인코딩 변경은 적용 전까지 초안이며 언어·용어·맥락은 초기화하지 않는다.
- 준비된 청크/결과가 있는 인코딩 변경은 별도 확인이 필요하다. 기존 암호화 청크, 전사 원문/수정본, 정리 생성본/수정본과 비교 결과를 함께 지운다. 원본 음성, 메모 정보·언어/힌트·정리 설정과 모델/키는 유지한다. 기존의 결과 보존을 위한 설정 잠금은 이 명시적 초기화 경로로 대체하되, 확인 없이 기존 onAudioOptions를 호출하는 변경은 계속 거절한다.
- 초기화는 원본의 실제 소유/보관/암호문 바이트를 검증하고, 정확한 설정·저장 버전에 묶인 단회 확인으로만 진행한다. 오래된 확인·작업 중·원본 부재·잠금/취소·저장 실패에서는 기존 파일/결과를 지우지 않는다. 기존 기술 제약상 삭제된 원본의 일치를 검증할 바이트가 없으면 재연결로 검증을 우회하지 않으며 새 메모에서 가져오도록 안내한다.
- 청크 파일 삭제와 암호화 프로젝트 교체는 하나의 transaction으로 수행한다. 원시 응답/본문/편집본/오류 응답을 제거하고 호출/사용량 메타데이터만 `processingArchives`에 남겨 초기화 이전 기록으로 보인다. 현재 청크 통계에는 과거 기록을 섞지 않는다. 준비가 완료되어도 유료 STT/LLM은 자동 실행하지 않는다.

[선별 검사·실제 브라우저와 제한](superpowers/evidence/2026-10-17-history-preparation-reset/README.md). 기존 사용자 App.tsx 문구 두 수정은 보존하며 해당 문구를 커밋에 포함하지 않는다.

## 2026-10-17 정리 분량과 추가 지침만 사용

사용자는 출력 예산의 숫자 입력을 4K/8K/16K/직접 입력으로 바꾸고 초보자가 이해할 수 있게 설명할 것, 전사문 전송·요금 확인과 음성 미재전송 안내를 합칠 것, 항목을 모두 끄는 `추가 지침만 사용`을 추가할 것을 요청했다. 또한 3단계 생성 버튼이 비활성이라고 확인했다. 실제 사용자 보관함/키/전사문은 읽지 않았으므로 당시 선택 상태의 개별 원인을 단정하지 않는다.

- 분량은 4K=4096, 8K=8192, 16K=16384로 기존 메모별 출력 예산에 연결한다. 선택 시 저장하고 확인을 해제한다. 직접 입력은 명시적 적용을 유지한다. 모델에 등록된 한도를 넘는 선택지는 차단하며 한도를 임의로 늘리지 않는다.
- 표시 이름은 `정리 분량`, 선택지는 `4K · 짧게 / 8K · 자세히 / 16K · 길게 / 직접 입력`이다. 최대 답변 길이이며 실제 분량은 원문·지침·언어에 따라 다르고 더 큰 선택은 시간과 비용이 늘 수 있다고 안내한다. 검증하지 않은 페이지/글자 수로 환산하지 않는다.
- `추가 지침만 사용`은 sections=[]를 저장한다. 비어 있지 않은 추가 지침이 있으면 실제 요청 검증/사전 적합성/생성을 허용하고 기본 항목을 강제로 추가하지 않는다. 항목과 지침이 모두 비면 실행을 차단한다. 근거 준수·미확인 발화·부분 전사 고지와 외부 동작 금지 규칙은 유지한다.
- 기존 템플릿을 사용하는 system prompt와 버전은 그대로 유지한다. 새 sections=[] 입력에서만 지침 기반 구조 규칙을 선택한다. 저장된 기존 비교 요청의 텍스트를 이번 변경으로 바꾸지 않는다.
- 확인 문구는 `선택한 전사문과 설정이 전송되고 요금이 발생할 수 있다는 것을 확인했어요. 음성은 다시 보내지 않아요.`로 합친다. 별도 반복 안내는 제거하고 전송 대상/정책·부분 전사 확인은 유지한다.
- 비활성 이유와 실행 가능 여부를 하나의 조건에서 판단하고 버튼에 연결된 접근성 상태로 표시한다. 전사문/모델 미선택, 추가 지침 누락, 미적용 언어/분량, 적합성 실패, 진행 중, 전송 확인 누락 등을 구분한다. 검증/명시적 전송 확인을 우회하지 않는다.

[관련 검증과 실제 화면](superpowers/evidence/2026-10-17-notes-length-instructions/README.md). 처리 기록 페이지와 청크 재설정은 앞서 제안한 별도 범위이며 이번 변경에 포함하지 않았다.

## 2026-10-17 전사 입력과 메모 정리 옵션

사용자의 최신 요청으로 전사 상세를 항상 표시하고, 전송할 언어·용어·맥락을 확인·수정할 수 있게 한다. 이전의 기본 접힘 결정은 이 결정으로 대체한다. 단순 안내와 달리 기존 실제 전사 요청은 용어·맥락을 빈 값으로 넘겼으므로 데이터 흐름도 함께 연결했다.

- 용어·맥락은 해당 메모의 암호화 저장 설정이며 공통 모델 설정을 덮어쓰지 않는다. 용어는 최대 50개/각 100자, 맥락은 2,000자로 제한한다. 적용 전 수정은 실행을 차단하고 동의를 해제한다.
- OpenAI의 검토된 전사 모델은 prompt, MAI Transcribe 2는 Azure의 `provider.options.azure.phraseList.phrases`에 용어를 매핑한다. MAI 용어는 Azure 처리 경로에서만 적용될 수 있다. 기타 호환 서버는 등록된 prompt/keywords 설정을 따르며 실제 서버 지원은 별도 확인이 필요하다. 지원하지 않는 맥락을 전송한다고 표시하지 않는다. [OpenAI 문서](https://developers.openai.com/api/docs/guides/speech-to-text), [OpenRouter STT 문서](https://openrouter.ai/docs/guides/overview/multimodal/stt)를 기준으로 요청 형식을 확인했으며 인증 추론은 검증하지 않았다.
- 요청 묶음은 언어·용어·맥락을 고정한다. 기존 묶음에 새 필드가 없으면 이후 메모의 값을 끌어오지 않는다. 취소/실패 재시도도 원래 입력을 사용한다.
- 어려운 보관 정책 문구를 `개인정보 보호 조건을 충족하는 제공사가 없으면 전사를 진행하지 않아요.`로 바꾼다. 실제 정책 차단은 유지한다.
- 메모 정리는 같은 폭의 왼쪽 모델/정리 설정/실행, 오른쪽 결과로 나눈다. 960px 이하에서는 설정 다음 결과 순서로 쌓는다. 전사문을 재사용하며 출력 설정 변경이 STT를 다시 실행하지 않는다.
- 출력 언어는 설정의 관리된 언어 목록에서 항상 선택할 수 있다. 앱 언어 따르기와 임의의 직접 입력도 보존한다. 직접 입력은 명시적 적용으로 저장한다.
- 출력 예산은 모델에 설정된 한도와 구분해 메모별 양의 정수로 수정·적용한다. 실제 token 필드, 문맥 적합성, 예상 비용, 동의 토큰과 비교 요청에 반영한다. 한도 초과·필수 한도 누락을 우회하지 않으며 저장된 비교 재시도는 원래 예산을 유지한다.
- 모델 선택에는 짧은 등록 이름을 사용하고 실제 모델 ID/경로는 작은 글씨로 보인다. 저장된 결과는 생성 당시 모델 이름을 사용한다. 모델의 미확인 제작자/요금/한도/소요 시간 행과 중복 설명을 제거하고, 확인된 요청 옵션은 펼침 버튼 없이 표시한다. 필수 한도 부족과 초과 경고는 유지한다.
- 확인 문구: `전사문이 전송되고 요금이 발생할 수 있다는 것을 확인했어요.`

[선별 검사·실제 화면과 한계](superpowers/evidence/2026-10-17-input-hints-notes-layout/README.md). 기존 사용자 App.tsx의 두 문구 수정은 보존하고 이 작업의 커밋에서 제외한다. 레퍼런스 원본은 수정하지 않는다.

## 검토 결과와 확정된 후속 결정

제공된 standalone은 실제로 열리고 조작 가능한 **제품 화면·동작·문구의 기준**이다. 다만 오디오 준비, STT, 회의록 생성, 암호화 저장과 재개를 구현한 실제 앱은 아니다. 화면을 임의로 다시 디자인하거나 이 샘플의 타이머·고정 결과를 제품 기능으로 옮기는 방식은 사용자의 목표와 맞지 않는다. 기존 문서는 기술 구조의 기준으로 유지하고, 충돌은 아래처럼 결정과 제안을 구분해 처리한다.

이번 검토 중 사용자가 직접 선택하거나 추가한 요구는 다음과 같다. 실제 자격 증명 입력·보안 설정 변경을 허용한 것이 아니라 **앞으로 구현할 제품 요구사항**이다.

## 2026-10-17 전사 좌우 배치와 청크 상태 정리

사용자 후속 요청에 따라 왼쪽은 전사 모델/전송 전 확인, 오른쪽은 처리 상태/청크 목록으로 나눈다. 두 열은 동일 폭이며 기존 960px 반응형 기준에서 설정 묶음 → 결과 묶음 순서의 동일 폭 단일 열로 쌓는다. 아래 전사 검토/사용량 명세의 전체 폭은 유지한다. 첨부한 청크 조작 화면의 정렬 지적에 따라 번호/시간/처리 상태와 버튼 행을 분리하고 재생·정지·재시도 버튼의 윗선을 맞춘다. 기본 `정지됨`은 화면에서 숨기되 정지 후 접근성 알림은 유지하며 실제 재생/일시정지/불러오기/오류와 보관 음성 안내를 유지한다.

`0 / 4 저장된 결과 있음`은 `전사 결과 0 / 4`, 미실행 제목은 `전사 대기 중`으로 바꾼다. 결과 개수는 기존처럼 암호화 저장 완료된 청크 결과만 세고 수신/저장 중 응답을 포함하지 않는다. 동의·재시도·저장/재생 코어는 변경하지 않는다. [실제 변경·검사 명령·Chrome 화면·한계](superpowers/evidence/2026-10-17-transcription-columns/README.md)를 따른다. 원본 레퍼런스는 보존한다.

## 2026-10-17 전사 선택과 상세 정보 간소화

사용자 후속 요청에 따라 전사 모델 선택지에는 짧은 등록 이름/별칭만 표시하고, 같은 이름은 실제 모델 ID와 서버 host로 구분한다. `제작자 확인 불가`는 공통 메타데이터 표시 규칙에서 오던 문구이며 전사 선택에서 제거한다. 정상 전송 확인은 대상과 요금 발생 가능성/제공사 보관·학습/로컬 암호화 한계를 바로 보여주고, 실제 endpoint·모델 ID·청크 수·측정 바이트·전송 내용·언어·보관 요청 등은 기본으로 접힌 `상세 보기`로 옮긴다. 미확인 총비용·처리 제공사·미확인 공개 요금 placeholder는 제거하며, 확인된 공개 단가는 상세에서 실제 청구와 구분한다. OpenRouter의 동적 경로·보관 조건과 실행 차단 사유는 유지한다.

재시도도 같은 상세 펼침을 사용하되 원래 묶음 조건·선택 범위·이전 자료 보존·추가/중복 비용 고지와 별도 확인을 유지한다. 선택 변경 시 기존 확인 해제, 최초/재시도 토큰·키 누락 차단, 저장/외부 전송 로직은 변경하지 않는다. [실제 변경 파일·명령·Chrome 화면·검증 한계](superpowers/evidence/2026-10-17-transcription-details/README.md)를 따른다. 원본 레퍼런스는 보존한다.

## 2026-10-17 입력 탭과 녹음 상태 표시 구현

사용자가 후속 설계와 구현을 승인했다. **아래 결정이 같은 날의 앞선 오른쪽 카드 순서를 대체한다.** 왼쪽 메모 정보는 유지하고 오른쪽은 `음성 추가`의 `마이크 녹음 / 파일 업로드` 탭 → `전사 준비` 순서다. 공통 현재 음성 정보·미리듣기·청크·압축과 실행 버튼은 아래 전사 준비 카드에 둔다. 탭 전환은 음성을 삭제하거나 교체하지 않으며 녹음·일시정지·저장과 다른 작업 중에는 전환을 막는다.

녹음 중 실제 PCM에서 계산한 입력 음량 막대를 표시하고, 녹음 길이는 `시:분:초`, 녹음 용량은 처음부터 완료까지 MB 소수점 두 자리로 고정한다. 시간은 수집된 샘플 기준이며 일시정지 중에는 증가하지 않는다. 입력 음량은 상대 신호 크기이고 음성/화자 감지·물리 소음계가 아니다. 완료 용량은 확정된 WAV 원본 바이트를 사용하며 암호화 저장 확인량과 구분한다. 저장 실패·중단·잠금 경계와 실제 전사 전 확인은 유지한다.

사용자는 전체 화면·전체 스위트의 반복 검사를 피하도록 명시했다. 녹음 코어·녹음 UI·입력 탭과 직접 관련된 잠금 경계를 선별하고, 별도 headful Chrome은 데스크톱 합성 녹음 1흐름과 좁은 화면 업로드 1흐름만 확인했다. 실패한 데스크톱 시험 입력을 보완한 뒤 해당 흐름만 재실행했다. 실제 명령·성공/실패·화면·제한은 [입력 탭·녹음 검증 기록](superpowers/evidence/2026-10-17-recording-input/README.md)을 따른다. 실제 키·물리 마이크·운영 배포는 사용하지 않았다.

## 2026-10-17 음성 준비 화면 재배치 승인

사용자는 왼쪽에 메모 정보, 오른쪽에 음성 작업을 배치하는 아래 제안에 “좋았어”로 동의한 뒤 제품 구현과 관련 테스트·실제 브라우저 확인을 직접 요청했다. **디자인 확정 후 로컬 구현·검증을 완료했으며 배포는 수행하지 않았다.** 화면 배치는 아래 최신 결정이 이전 레퍼런스보다 우선하며, 원본은 보존한다. 실제 변경 파일·명령·화면과 한계는 [재배치 검증 기록](superpowers/evidence/2026-10-17-preparation-layout/README.md)을 따른다.

| 영역 | 확정한 구성 |
| --- | --- |
| 본문 왼쪽 약 40% | 메모 제목 → 아이콘 선택 → 색상 선택 → 사용 언어 복수 선택 → 언어 안내 |
| 본문 오른쪽 약 60% 최상단 | 현재 음성·준비 상태, `음성 준비`와 `전사하기 →` 버튼, 청크·압축 요약과 `처리 설정 펼치기` |
| 오른쪽 두 번째 카드 | 마이크 녹음 상태·시간·조작 |
| 오른쪽 마지막 카드 | 음성 업로드, 파일 선택·선택한 파일 정보·미리듣기 |
| 청크·압축 표시 | 현재 청크 길이(분)·겹침(초)·압축 형식을 항상 요약하고 세부 설정만 접는다. 제안 그림의 10분·10초는 예시이며 저장값·기본값 변경 결정이 아니다 |
| 주요 행동 | 준비 전에는 `음성 준비`, 준비 완료 후에는 `전사하기 →`를 강조한다. 전사 버튼은 기존 모델·외부 전송·요금 확인 화면으로 이동하며 직접 추론을 시작하지 않는다 |
| 힌트 | 자유 입력 STT 힌트·용어집은 이번 범위에 추가하지 않는다. 기존 사용 언어 선택과 모델별 언어 힌트 적용 방식을 유지하고 언어 안내를 제공한다 |
| 설명·디자인 | 기존 글꼴·팔레트 유지, 카드 제목·내부 여백·선택 스타일 통일, 주요 행동만 강조색 사용. 공통 처리 설명은 최상단에 한 번, 녹음·업로드에는 행동별 안내만 표시한다 |

공통 문구는 “음성 준비는 이 브라우저에서 진행돼요. 전사는 다음 단계에서 전송 내용과 요금을 확인한 뒤 실행해요.”로 정리한다. 지원 형식·코덱 설명은 `지원 형식 보기`로 접고, 녹음 권한 안내·실패·데이터 보존/교체 제한·전사 전 확인은 해당 행동 옆에서 확인할 수 있도록 유지한다. 기존 확정 언어 안내 문구의 의미는 바꾸지 않는다.

이번 설계에 앞서 Chrome의 별도 `🎨 MoM 화면 검토` 창에서 원본 standalone의 가져오기 화면을 렌더링하고 현재 로컬 음성 준비 화면의 파일 선택 상태와 비교했다. 화면 캡처는 각각 1269×919였으며 새 배치 시안의 렌더링 증거는 아니다. 실제 녹음·파일 업로드·준비·전사 실행은 이번 검토에서 수행하지 않았다. 적용 파일과 후속 확인 범위는 [이번 재배치 구현 계획](12-implementation-plan.md#2026-10-17-음성-준비-화면-재배치-구현-계획)을 따른다.

> 이 브라우저에 저장한 데이터는 암호화로 보호돼요. 전송된 음성의 보관·학습 여부는 제공사 약관과 계정 설정을 따라요.

행 삭제는 전송 범위 변경을 뜻하지 않는다. 원본 영상·다른 회의 데이터는 보내지 않고 일반 전송 파일명을 사용하는 기술 제약과 요청 검증은 유지한다. “언어 힌트”는 선택 모델이 지원해 실제 요청에 포함되는 경우만 표시하며, 다른 언어를 제외하지 않는다는 안내는 앱의 언어 필터 정책이지 모델의 전사 정확성 보장이 아니다. 암호화 안내는 실제 암호화 저장을 구현·검증한 제품에서 사용한다.

**설정의 라이선스 배치안:** “제3자 라이선스”와 “제3자 소스 · 재빌드 · 재연결” 링크를 설정 하단에 표시하고 기존 새 탭 동작·키보드 접근성을 유지한다. 대상은 각각 `/THIRD_PARTY_NOTICES.txt`, `/sources/REBUILD.md`이며 로컬 포트 주소를 하드코딩하지 않는다. 고지 파일·라이선스 원문·기존 제3자 소스·재빌드·재연결 자료는 배포 자산에 보존한다. 링크 이동은 자료 삭제, MoM 소스 공개 범위 확대나 라이선스 조건 변경을 뜻하지 않는다. 빌드 배너를 제거해도 인증된 실제 AI·품질의 미검증 이력과 출시 조건은 검증 문서에 남긴다.

**이번 확인 범위:** 2026-10-01 Chrome의 별도 `🔎 MoM 문구 검토` 창에서 원본 standalone의 데모 잠금 해제와 파일 없는 가져오기 화면을 1616×1348 뷰포트로 렌더링하고 스크린샷·접근성 트리를 확인했다. 원본에는 “파일을 먼저 가져오세요”, “선택한 언어는 전사 요청에 힌트로 전달돼요. 모델에 따라 첫 번째 언어만 반영될 수 있어요.”와 “보내지 않는 것” 행이 있다. 새 문구의 제품 화면 적용·줄바꿈·실제 전송·암호화 동작은 검증하지 않았으며 G03·G09·G10의 상태를 바꾸지 않는다.

후속 빌드 안내 요청의 `http://127.0.0.1:4184/`는 브라우저에서 연결 거부로 열리지 않았다. 로컬에 기록된 `origin/main`의 `src/react-app/App.tsx`에서 공유 `BuildQualification`이 `VaultGate`와 잠금 해제 후 사이드바에 각각 한 번 호출되는 것을 확인했다. `Settings.tsx`의 기존 설정 화면과 `public/sources/REBUILD.md`의 연결 자료 설명도 읽기 전용으로 확인했다. 사용자가 배포 주소로 정정한 뒤 `https://mom.korgeek.workers.dev/`를 별도 in-app browser에서 열어 새 보관함 만들기 화면의 배너와 두 링크를 접근성 트리로 확인했다. 암호 입력·보관함 생성·잠금 해제는 수행하지 않아 잠금 해제 후 위치는 사용자 관찰과 소스 확인을 근거로 한다. 링크 이동·배너 제거 후 화면이나 운영 배포를 검증한 것은 아니다.

사용자의 최신 결정 → 화면·동작·문구는 제공된 레퍼런스 → 기술 구조는 01~06·08~10 문서의 역할로 읽는다. [07 화면 목록](07-design-feature-inventory.md)은 먼저 작성된 제안이며, 실제 레퍼런스를 대신하는 새 디자인 사양이 아니다. 보안·동작 충돌은 사용자 결정 또는 검토된 기술 설계로 해결하고 원본 파일은 보존한다.

## 체크아웃 상태와 구현에 미치는 영향

검토 시작 시 `main`의 HEAD와 로컬에 기록된 `origin/main`은 템플릿 커밋 `102086a`였다. 로컬 ref 기준 ahead/behind는 0/0이다. 추적 파일은 최상위 README와 Wrangler 설정뿐이며 `src/`, `package.json`, 제품 빌드 산출물은 없다. 기존 `docs/`와 `.DS_Store`는 사용자 미추적 파일이다. 적용할 기존 AGENTS.md나 체크아웃의 `.agents/skills`는 발견하지 못했다. 기존 문서가 충분한 이력을 담고 있어 별도 Codex 메모리·비밀 파일을 읽지 않았다.

기존 문서에는 원격 main의 `7f60ce8…` 소스 가져오기 커밋이 후속 조회됐다는 기록이 있다. 이번 `git ls-remote origin refs/heads/main`은 DNS 해석 실패로 끝났다. **로컬 ref의 일치가 현재 GitHub main과의 일치를 증명하지 않는다.** 구현 시작 시 실제 원격과 로컬 차이를 읽기 전용으로 재확인하고 사용자 미추적 문서·레퍼런스를 보존해야 한다. 이번 작업은 fetch/pull/reset 또는 사용자 파일 덮어쓰기를 하지 않았다.

## 실제 브라우저 검토 범위

Mac mini의 Chrome에 `🔎 MoM 참고 검토` 별도 테스트 세션/창을 만들고 원본 standalone을 표시했다. 브라우저 도구는 `file:` 직접 탐색을 허용하지 않았다. 보안 설정을 바꾸지 않고 승인된 `127.0.0.1:8773` 전용 임시 읽기 서버로 제공했다. 이는 레퍼런스 검토 도구이며 MoM 제품 서버가 아니다.

## 기능과 모의 동작의 구분

제품 스크립트에는 provider `fetch`, IndexedDB, localStorage/sessionStorage, Web Crypto, AbortController, Clipboard API 호출이 없다. `support.js`의 fetch는 런타임·자산 처리이며 인증된 STT가 아니다.

| 분류 | 소스 근거와 의미 |
| --- | --- |
| 실제 UI 상태 동작 | `go`, 언어/테마/옵션 변경, 검색, `saveEdit`, Markdown 텍스트 편집은 메모리 상태를 바꾼다. 새로고침을 견디는 저장과 구분한다 |
| 파일 선택/재생 경로는 존재 | `loadFile`은 File의 크기/이름, Audio 메타데이터와 재생을 사용한다. 개인/합성 실파일로 이 경로를 시험하지 않았으므로 포맷 지원을 인증하지 않는다 |
| 로컬 준비·STT는 모의 | `buildChunks`는 시간·예상 크기 계산. `tick`은 250ms마다 무작위 진행률을 올린다. 실제 demux/인코딩/압축/AI 응답 저장은 없음 |
| 전사·겹침·재생은 샘플 | `SEGS`, `OVS`가 고정 텍스트. 청크/문장 재생은 시각·시간 상태 변화이며 실제 청크 오디오 연결이 없음 |
| 회의록·추천 제목·비교는 모의 | `buildMd`는 고정 `MD` 섹션을 조합. 입력 전사 수정·추가 지침을 내용에 반영하지 않는다. `generate`는 1.4초 타이머 뒤 임의 8~14초 메타데이터를 표시. `CMP`/`LOG`도 고정 데이터 |

| 내보내기 구현은 있음, 완료 미확인 | `downloadMd`는 현재 텍스트의 Blob과 다운로드 링크를 만든다. 이번 도구에서 실제 파일 완료는 확인하지 못했다. 클립보드 복사 구현은 없음 |

## 충돌·누락과 우선순위

**구현을 막는 핵심 항목:** 실제 저장/잠금 경계, 실제 긴 오디오 준비, provider 연결과 원시 결과 저장, 전사 정합성과 결과 생성의 연결이다. 화면 장식과 모델 비교 확대보다 먼저 해결해야 한다.

1. **암호화·키 수명·잠금(P0):** 암호화 저장 기본과 잠금 후 새 작업 중지는 사용자 결정으로 해결됐다. AES-GCM 256/PBKDF2 600,000회·6자리 PIN 문구는 검토된 보안 사양이 아니다. 최초 비밀값 설정, 잘못된 비밀값/손상 암호문, 저장 실패, 키 지우기/변경, 멀티탭·진행 중 요청을 설계하고 저장소 평문·DOM 잔류를 시험해야 한다. 샘플의 실패 횟수 안내와 실제 30초 차단 구현도 일치하지 않는다.
2. **긴 오디오·상태(P0):** 실제 준비 경로가 없다. 샘플의 15분·15초 선택 뒤 청크 행은 15분인데 머리말은 고정 10분·10초다. 샘플 상태 전환은 10분·10초 계획으로 돌아가면서 겹침 표시가 현재 선택값을 읽기도 한다. 실제 실행의 계획/설정/바이트를 한 기준으로 기록해야 한다. 저장 실패, 크기 초과, 디코딩 실패, 메모리 한계와 결과 불명을 별도 상태로 다룬다.
3. **원시 전사·겹침(P0):** 렌더링된 검토 화면은 “겹침 구간은 병합하지 않고 그대로 보여줘요”라고 안내하며 원본 청크만 보인다. 병합/겹침 대안용 로직은 있지만 템플릿에 연결되지 않는다. 같은 `segs`를 수정해 원본 화면에도 반영하므로 원시 결과가 보존되지 않는다. 원시/수정본을 분리하고 전체 회의 생성 전에 중복·누락을 정리해야 한다. 별도 병합 검토의 화면 위치는 **제안**으로 후속 계획에 정한다.
4. **다국어·최종 의미(P0):** 복수 입력 언어와 독립 출력 선택은 좋은 기준이다. 실제 모델 힌트·시간·화자 능력은 별도 검증해야 한다. 고정 MD는 누락된 청크 3의 A/B 테스트·대시보드 내용도 포함하고, “추가 지침 반영”이라고 표시하면서 표 요청은 반영하지 않는다. 실제 전체 선택 전사에 근거한 생성과 긴 문맥 제한 처리가 필요하다.
5. **편집·복사·다운로드(P0/P1):** 재생성은 편집본을 덮어쓴다. 수정본/생성 원본 보존과 사용한 전사 버전 표시가 필요하다. 복사는 사용자의 명시적 클릭으로 현재 최종 텍스트만 대상으로 한다는 안을 권장한다. 잠김·빈 결과·클립보드 권한 거절/지원 밖 환경·다운로드 실패 상태를 시험한다. 복사/내보내기한 평문은 저장소 암호화의 보호 범위 밖이다.
6. **전송 고지·접근성(P0/P1):** STT의 전송 전 확인은 실제 앱에 유지할 기준이다. 텍스트 생성·비교에서는 전사/지침과 OpenRouter 하위 제공자로 가는 경로·추가 비용이 더 명확해야 한다. 잠금 배경을 DOM/접근성에서 제거하고 대화상자 초점 제한/복귀, 섹션 체크·순서 버튼·색상 버튼의 이름/상태, 오류 읽기와 키보드 탐색을 확인한다. 화면 문자열 “파일명은 보내지 않음”은 실제 요청의 filename 필드까지 일치해야 한다.

**합리적 기본안(아직 사용자 승인된 추가 사양은 아님):** 샘플 기본 화면·코발트·Pretendard·10분/10초를 첫 검증 기준으로 유지하고, 먼저 한 provider 실행과 현재 전사 재사용을 연결한다. 실패 청크만 선택 재시도하고 암호화 저장 완료를 체크포인트로 삼는다. 숫자·부정어·고유명사·결정 번복·담당자 미정 사례를 품질 평가 입력에 포함한다. 실제 모델/가격은 샘플 상수로 고정하지 않는다.

**후속 확장:** 전체 녹음의 다중 STT 비교, 대량 동시 모델 비교, 임의 템플릿 가져오기·복구 키/암호화 백업, 추가 코덱·모바일 실행은 첫 시험 빌드의 핵심 완결성과 구분한다. 샘플에 있는 편의 요소도 실구현·검증 전에는 완료 표시하지 않는다.

현재 문서 작성을 막는 필수 사용자 결정은 없다. 부분 전사 생성은 샘플처럼 누락 경고를 유지하는 것을 출발 제안으로 삼을 수 있으나, 전체 회의 결론으로 표시하면 안 된다. 암호 강도·복구·KDF와 긴 문맥 처리 등은 구현 계획에서 구체적 기술안/검증 한계를 남기고 사용자 결정을 임의로 만들지 않는다.

## 후속 구현의 검증 조건과 이번 검토 한계

화면 충실도와 실제 기능은 각각 검증한다. [G01~G12](08-verification-and-release-gates.md)의 상태는 이번 프로토타입 조작으로 통과하지 않는다. 실제 파일 → 유효한 청크 → 허용된 인증 STT → 암호화 저장 → 선택/수정 전사 → 근거 있는 회의록 → 편집/복사/`.md`까지 연결돼야 완성 기능으로 볼 수 있다.

키 없는 로컬 처리·암호화·상태·fixture provider 시험을 실제 추론과 구분한다. 실제 키는 아직 제공되지 않았다. 기존 비밀 파일을 찾거나 읽지 말고, 별도 제한된 테스트 키를 사용자가 실제 앱 UI에 직접 입력하는 방식을 우선한다. 채팅/Git/`VITE_` 환경변수에 키를 넣지 않는다. gitignore는 비밀 보호 보장이 아니다. 실제 자격 증명 입력·전송과 유료 호출은 사용자에게 넘기는 승인 절차가 필요하며 무인 시험의 전제조건으로 가정하지 않는다.

기존 OpenAI/OpenRouter 결과는 키 없는 전송·401 또는 공개 목록 GET 근거다. Cloudflare Workers AI는 기록된 조건의 직접 CORS가 실패했다. 이번 작업은 이를 재시험하지 않았으며 인증 STT·암호화 구현·다국어 품질·회의록 품질·운영 준비를 검증하지 않았다. 브라우저 콘솔의 이번 마지막 캡처에는 warn/error가 없었지만 이것도 기능·보안 통과 증거가 아니다.

원본 레퍼런스의 해시는 작업 전후 비교로 보존 여부를 확인한다. 후속 구현 계획은 별도 산출물이며, 사용자 검토 후 의미 있는 기능 단위로 실행한다. main 푸시 전 실제/fixture 시험 구분, 보안·저장·오류 검사와 배포 가능 여부를 확인하고, 성공한 푸시 뒤에도 실제 서비스 응답·자산·화면·기능을 브라우저에서 확인한다.

## 2026-10-19 전사 확인 모달과 왼쪽 사용량 요약

사용자가 대화의 모든 개선을 구현·배포하도록 승인했다. 이 최신 결정은 앞선 동일 폭 STT 열과 하단 인라인 전사/사용량 배치, 보관 원본의 미리듣기 파일 재선택, 재시도 모델 고정 UI를 대체한다. 왼쪽 240–300px 모델/전송 확인/사용량 요약과 오른쪽 결과/청크, 청크별 원본 모달, 진행 카드의 전체 전사 편집 모달, 별도 명세 모달을 사용한다. 모델 변경은 새 묶음과 새 비용 확인으로 처리하고 원본·수정본을 유지한다. 실제 파형/재생과 메모 헤더의 전체 작업 삭제를 연결했다. 데스크톱 타이머만 잠금 버튼 위로 이동하며 모바일 위치는 유지한다. [구현·명령·실제 Chrome 화면·제한](superpowers/evidence/2026-10-19-review-audio-release/README.md)을 따른다. 원본 레퍼런스는 보존했다.

## 2026-10-19 전사 범위와 사용할 원본 확정 후속

사용자 후속 스크린샷/요청에 따라 저장된 청크가 현재 선택 전사에 없다는 이유로 개별 재전사를 막지 않는다. 청크 모달은 열람과 `이 결과 사용`을 구분하고 사용 중 표시를 제공한다. 전체 실행은 완료된 청크 건너뛰기와 전체 다시 전사, 실제 전송 개수·모델·추가 요금 확인을 모달에서 선택한다. 기존 원본·전사/수정본·노트는 보존하며 다른 청크 수정과 무관한 겹침 확인을 유지한다. [실제 선별 검사·화면·한계](superpowers/evidence/2026-10-19-stt-scope-choice/README.md).
