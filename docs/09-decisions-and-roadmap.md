# 결정 기록과 다음 로드맵

**2026-10-18 API 정책·프리셋 배포 승인:** 사용자는 작업 계획을 승인하고 검증 후 커밋·배포까지 진행하도록 요청했다. 앞선 이 변경의 로컬 전용 범위를 main 정상 푸시와 기존 Cloudflare 자동 배포까지 확장했다. 동일 코드·빌드·도구 버전의 관련 테스트 148개·로컬 화면·빌드 증거를 재사용하고 배포 dry-run, 운영 자산 SHA-256/보안 헤더와 변경 화면만 추가 확인했다. 실제 키·사용자 보관함·유료 추론은 포함하지 않는다. [배포 결과](superpowers/evidence/2026-10-18-model-api-presets/release/README.md)에 실제 버전과 한계를 기록했다.

**2026-10-18 OpenRouter 정책·프리셋 후속 결정:** 사용자는 OpenRouter 전송·보관 선택과 확인을 새 모델 폼에서 API 등록으로 이동하고, 종류 다음에 제공사를 구분한 프리셋을 선택해 이름·주소·모델 ID·인증을 채우도록 요청했다. OpenRouter STT 5개·LLM 4개도 지정했고, 작업 지침의 문서 전용 범위를 확인한 뒤 실제 앱 코드 수정을 명시적으로 승인했다. 이 범위에 한해 로컬 구현·의미 있는 커밋을 진행하며 푸시·배포·실제 자격 증명·유료 추론은 포함하지 않는다. API에 저장한 정책이 연결 STT·LLM에 적용되고 정책 변경 시 기존 테스트와 미실행 전송 확인을 갱신한다. 기존 API에 정책이 없는 경우 기존 모델 정책을 그대로 보존하며, API 정책을 처음 저장할 때 사용자가 명시적으로 확인한다. 새 LLM 폼도 OpenRouter를 초기 API로 쓴다. 이는 10월 17일 모델별 정책 설정·확인 배치의 후속 변경이다. [변경·검증 기록](superpowers/evidence/2026-10-18-model-api-presets/README.md)에 실제 검증과 한계를 남겼다.

**2026-10-18 모바일 단계 개선 병합·배포 승인:** 사용자가 앞선 로컬 결과 `2fe1467`에 대해 “머지 커밋 푸시 배포 합시다”라고 요청했다. 아래 10월 17일의 로컬 전용 범위를 변경해 main 병합 커밋·일반 푸시와 기존 Cloudflare 자동 배포, 실제 운영 모바일/PC 확인, 이번 작업트리·브랜치의 안전한 정리를 승인했다. fetch한 원격 main은 `70ff273` 그대로였고 추가 제품 변경 없이 완료 코드를 통합한다. 기존 통과 검증을 재사용하고 통합 빌드·산출물과 배포 후 변경 기능을 확인한다. 실제 키·유료 AI·사용자 보관함이나 다른 미병합 작업은 이 승인에 포함하지 않는다. 배포 성공은 실제 빌드/운영 자산과 화면을 확인한 뒤 별도 완료 근거로 보고한다.

**2026-10-17 모바일 단계·완료 상세 후속 결정:** 배포 후 사용자가 1·2·3 단계를 한 줄로 배치하고 완료한 단계의 상세를 접도록 요청했다. 모바일은 기존 세 단계 이동을 같은 폭의 한 줄로 유지하며 별도 단계 목록은 추가하지 않는다. 자동 완료 순간에는 펼친 화면을 유지하고, 다음 단계로 명시 이동한 뒤 돌아온 완료 상세만 요약으로 접는다. 준비의 제목·언어와 전사의 선택 전사 검토, 최종 정리 결과·복사·다운로드는 유지한다. 아이콘·색상은 모바일에서 현재 선택 요약과 펼침으로 제공한다. 미저장·진행 중·실패·부분 결과·초기화 편집은 숨기지 않으며 PC 배치는 유지한다. 최신 main `70ff273` 기반 독립 작업트리의 로컬 구현·검증과 합성 전후 캡처 제공 범위이고, 이번 후속은 main 푸시·배포를 포함하지 않는다. [변경·검증 기록](superpowers/evidence/2026-10-17-mobile-stages/README.md)을 따른다.

**2026-10-17 Mac mini 업데이트·모바일 개선:** 사용자가 원격 main의 로컬 통합과 의존성·영향 검증, 이어 모바일 구현·검증을 승인했다. 모바일은 브랜드+⋯ 한 줄 헤더, 처리 기록·설정·잠금 아이콘/텍스트, 가로 스크롤 설정 탭, 세로로 읽는 보안 설명을 적용하고 PC 배치·보안 문구·데이터 정책을 유지한다. 실제 360/390/430px·PC 검토에서 발견한 작은 펼치기 영역도 모바일에서 넓힌다. [설계](superpowers/specs/2026-10-17-mobile-ui-design.md)와 [로컬 검증·전후 화면](superpowers/evidence/2026-10-17-mobile-ui/README.md)을 따른다. 원격 통합 기준선 실패와 모바일 결과를 구분하며 push·배포는 승인 범위 밖이다.

**2026-10-17 병합·배포 후속 승인:** 이후 사용자가 “메인으로 머지하고 배포합시다”라고 요청하고, 모바일 작업 기준의 원격 main이 MacBook 작업 완료 후 푸시한 최신본이며 이후 추가 작업은 없다고 확인했다. 앞선 로컬 전용 범위를 변경해 main 일반 푸시와 기존 Cloudflare 자동 배포·실제 운영 확인, Mac mini의 안전한 정리를 승인했다. 실제 키·유료 AI·자격증명 변경은 포함하지 않는다. 기존 실패 5개는 현재 화면 계약에 맞게 테스트만 수정했고, 영향 파일 4개의 126개 검사와 타입·린트가 통과했다. 배포 성공과 운영 확인은 실제 결과가 생긴 뒤 별도 근거로 보고한다.

## 결정 기록

**2026-10-19 Wrangler 관측 설정:** 사용자가 제시한 값을 실제 설정 파일 `wrangler.json`에 적용한다. `observability.logs`는 enabled/invocation_logs/persist를 true, head_sampling_rate를 1로 하고, traces는 enabled를 false, head_sampling_rate를 1, persist를 true로 둔다. 중복 TOML/JSONC 설정을 만들지 않으며 source map 비활성·정적 자산 구조는 유지한다. 브라우저의 회의 자료·키를 로그로 보내는 기능이나 AI 중계는 추가하지 않는다. 실제 원격 배포·로그 수집 확인과 로컬 설정 검증은 구분한다.

**2026-10-19 라이선스 적용 승인:** 사용자가 아래 초안대로 정식 라이선스를 적용하고 README와 앱 안내를 맞추되 LGPL 예외를 그대로 유지하도록 승인했다. [MoM Source Available License 1.0](../LICENSE)을 korgeek 권리자 표기와 2026-10-19 시행일로 MoM 자체 소프트웨어 및 그 배포물에 적용한다. 앱의 한국어/영어 요약은 정본인 한국어 약관을 대체하지 않는다. 원문은 루트 LICENSE와 앱 배포 사본이 동일하며 기존 recipient permission·제3자 라이선스·코덱 교체 권리는 보존한다. 아래 초안 단계의 미채택 기록은 과거 상태로 남긴다. 이번 요청에 저장소 공개·푸시·운영 배포는 포함되지 않는다.

**2026-10-19 소스 공개 라이선스 방향:** 사용자가 회사 내부의 회의록 작성과 자유로운 소스 열람·검증을 허용하고, 소스를 개작한 재배포와 다른 제품·유료 서비스 제공을 제한하며 LGPL 예외를 유지하도록 요청했다. 이 정책에 따른 [MoM 전용 라이선스 초안](16-mom-source-available-license-draft.md)을 작성한다. 정책 방향과 약관 채택은 별개이며 초안은 미채택이다. 내부용 수정·배포, 검증용 원본 공유·플랫폼 포크, 결과 문서 권리, 제3자 및 기존 배포 허용권의 우선 관계를 초안에 구체화하고 제안된 세부 경계는 별도로 표시한다. 권리자·적용 범위·시행일과 법률 검토를 거쳐 채택하기 전에는 기존 배포 조건·제품·저장소 공개 설정을 바꾸지 않는다. 커밋·푸시·배포를 승인한 요청도 아니다.

**2026-10-01 문구 결정:** 파일 없는 시작 안내를 “음성 파일이 준비되지 않았어요”로, 언어 안내를 “선택한 언어는 가능한 경우 힌트로 제공돼요. 다른 언어의 발화도 제외하지 않아요. 모델에 따라 힌트가 지원되지 않을 수 있어요.”로 교체하는 사용자 요청을 기록했다. “보내지 않는 것” 행 생략과 로컬 저장/외부 제공자 정책을 나눠 설명하는 새 표현은 편집 제안이다. 정확한 문구·상태·브라우저 확인 범위는 [레퍼런스 검토](11-design-reference-review.md)의 “2026-10-01 문구 조정”을 따른다. 전송 범위·암호화 요구·제공자 정책 또는 구현 승인 범위는 바꾸지 않는다.

**2026-10-01 빌드 안내 후속 결정:** 제3자 라이선스·소스 링크를 설정으로 이동하는 사용자 요청을 확정 배치 방향으로 기록했다. 사용자가 확인한 잠금 해제 화면과 잠금 해제 후 왼쪽 메뉴 상단의 두 위치 모두가 대상이며, 설정 한 곳에 모은다. 설정 하단 “앱 정보 · 라이선스” 섹션과 두 위치의 “테스트 빌드 · 실제 AI 미검증” 상시 배너 제거는 편집 제안이다. 기존 고지·라이선스·제3자 소스·재빌드·재연결 자료와 검증 한계 기록은 유지한다. 상세 배치·확인 한계는 [레퍼런스 검토](11-design-reference-review.md)에 남겼다.

**2026-10-02 실제 잠금 화면 변경 요청:** 배너 제거를 확정 변경으로 전환하고, `Minutes of Meeting (MoM)` 제품 이름과 암호 없이 접근 가능한 실제 보관함 초기화 기능을 잠금 화면에 넣는다. 삭제 범위 안내·명시적 최종 확인·취소와 다중 탭/저장소 실패 처리를 포함한다. 이 요청은 제품 기능 구현을 대상으로 하며 실제 사용자 데이터 삭제를 허용하는 요청은 아니다. 이전의 문서 반영만으로 완료로 보지 않는다. 수용 기준과 구현 누락의 확인 근거는 [레퍼런스 검토](11-design-reference-review.md)의 2026-10-02 기록을 따른다.

**2026-10-02 테스트 범위 결정:** 기본 검증은 Git 변경 내역과 직접 영향을 받는 호출부·데이터 흐름·화면 상태를 중심으로 필요한 최소 범위에서 수행한다. 변경과 무관한 전수 테스트·전체 스위트는 사용자가 명시적으로 요청할 때만 실행한다. 관련 테스트 실패만으로 전수 테스트를 추가하지 않으며, 변경 없는 항목의 기존 검증도 반복하지 않는다. 이번 보관함 초기화·브랜드 변경은 취소·삭제·실패·다중 탭 소유권·관련 잠금 동작과 제품명·배너·라이선스 배치, 해당 변경의 배포 확인을 대상으로 한다.

**2026-10-14 삭제 확인 입력 결정:** 보관함 전체 삭제의 확인 입력은 UI 언어와 무관하게 `delete`로 통일하고 대소문자를 구분하지 않는다. `delete`, `DELETE`, `DeLeTe`를 허용하며 별도의 최종 삭제 버튼 클릭이 필요하다. 한국어·영어 안내에 같은 입력값과 대소문자 무시를 표시한다. 삭제 범위, 취소, 소유권 및 저장소 실패 처리 요구는 유지한다.

**2026-10-17 홈 문구 마무리:** 사용자 요청에 따라 사이드바 상단 `LOCAL`을 제거하고 `회의 작업`을 `음성 메모`, 본문 `새 회의 만들기`를 `새 음성 메모`로 바꾼다. 대체 문구 선택을 맡긴 홈 메뉴는 `홈 · 음성 메모`로 정하고 같은 목록·생성 경로의 표현과 새 항목 기본 제목을 맞춘다. 기존 저장 제목·보관 방식·외부 전송·회의록 동작은 바꾸지 않는다. 이번 제품 문구 변경에 한해 구현을 진행하며, 구체적 변경 파일과 영향 범위 검증은 [레퍼런스 검토](11-design-reference-review.md)의 2026-10-17 기록을 따른다.

**2026-10-17 목록 관리 범위 축소:** 사용자 최신 결정에 따라 새 설정의 관리 대상은 색상과 음성 준비의 `사용 언어 · 복수 선택` 목록만이다. 아이콘 등록과 한국어·영어 문구 편집은 이번 범위에서 제외한다. 입력 언어의 임의 추가는 설정으로 옮기고 각 메모에서는 복수 선택한다. 기본값·암호화 로컬 저장·영역별 복원 및 이 두 목록의 JSON 가져오기·내보내기·AI 수정 안내에 대한 구체안은 [색상·입력 언어 설정 검토안](superpowers/specs/2026-10-17-color-language-settings-design.md)에 정리했다. 사용자가 같은 날 이 설계의 구현·로컬 커밋을 승인했고 배포는 금지했다. 승인 범위의 로컬 구현과 변경 영향 검증을 완료했으며 실제 명령·결과·한계는 [검증 기록](superpowers/evidence/2026-10-17-selection-lists/README.md)에 남겼다. 기존 `2a05a47` 커밋은 로컬에 유지하고 푸시·배포는 하지 않는다.

**2026-10-17 보안 재검증·배포 요청:** 사용자가 추가 수정·커밋·보안 재검증·푸시와 배포를 명시적으로 요청했다. 최신 저장 영수증과 늦은 실패 표시가 공존할 때 실패 재시도를 차단하고, 이전 결과를 보존한 새 실패 요청의 재시도는 유지한다. 기존 UI 실패 해결, 설정 입력/출력·암호화 저장·잠금·브라우저 검증과 한계는 [보안 재검증 기록](superpowers/evidence/2026-10-17-security-recheck/README.md)을 따른다.

**2026-10-17 음성 준비 재배치:** 사용자가 왼쪽 메모 정보 약 40%, 오른쪽 음성 작업 약 60% 구성을 승인했다. 오른쪽은 음성 준비·전사 버튼과 청크·압축 요약 → 마이크 녹음 → 음성 업로드 순서다. 자유 입력 STT 힌트는 추가하지 않고 기존 사용 언어 선택을 유지한다. 공통 설명과 카드 시각 규칙을 통일하며 전사 버튼은 기존 전송·요금 확인 단계로 연결한다. [확정 배치](11-design-reference-review.md#2026-10-17-음성-준비-화면-재배치-승인)와 [구현 계획](12-implementation-plan.md#2026-10-17-음성-준비-화면-재배치-구현-계획)에 기록했다. 후속 사용자 요청으로 제품을 구현하고 관련 단위·별도 headful Chrome 검증을 완료했다. 실제 명령·결과·한계는 [재배치 검증 기록](superpowers/evidence/2026-10-17-preparation-layout/README.md)을 따르며 푸시·배포·인증된 AI 추론은 포함하지 않는다.

**2026-10-17 입력 탭·녹음 표시 후속:** 사용자가 `마이크 녹음 / 파일 업로드`를 같은 음성 추가 카드의 탭으로 묶고 그 아래 `전사 준비`를 배치하도록 구현을 요청했다. 실제 입력 레벨, 샘플 기준 `시:분:초`, 녹음 중·완료 후 MB 두 자리 표시를 추가했다. 전수·반복 화면 검사를 피하라는 최신 요청에 따라 직접 영향받는 단위/경계와 브라우저 2흐름만 검증했다. [최신 설계·구현](11-design-reference-review.md#2026-10-17-입력-탭과-녹음-상태-표시-구현)과 [검증 기록](superpowers/evidence/2026-10-17-recording-input/README.md)을 따르며 앞선 오른쪽 카드 순서를 대체한다. 푸시·배포는 수행하지 않았다.

## 단계별 로드맵 제안

### 1 문서와 범위 검토

확정 요구와 첫 릴리스 후보를 검토하고 Q01~Q08, Q13~Q16을 중심으로 선택한다. 디자인 샘플은 핵심 흐름과 오류·잠금 상태를 보여주되 후보 기능 전체를 약속하지 않는다. 산출물은 승인된 범위, 지원 목표와 구현 계획이다.

### 2 위험이 큰 연결과 저장 검증

선택 포맷의 긴 실파일, 실제 운영 원점의 인증된 제공자 요청, 저장·새로고침·암호화·잠금 흐름을 검증하는 안이다. 사용자의 키·파일·비용 관련 실행은 별도 허용된 범위에서 수행해야 한다. 현재 문서 작업에서 실제 키나 유료 요청을 쓰지는 않았다. 실패하면 범위를 줄이거나 설계를 바꾼다.

### 3 핵심 흐름 구현

승인된 계획에 따라 파일 검사·로컬 준비, 청크 상태·원시 결과 저장, 전사 병합·검토, 선택 언어·항목의 회의록 생성, 편집·Markdown 내보내기를 연결한다. 암호화 저장과 잠금 요구는 핵심 데이터 흐름에 포함한다. 출력 변경으로 STT가 반복되지 않는지와 실패분만 재시도하는지 확인한다.

### 4 품질과 복구 검증

실제 다국어·겹침·숫자·화자·결정 수정 사례, 중단·저장 실패·잘못된 암호·손상 저장소·멀티탭을 시험한다. [G01~G11](08-verification-and-release-gates.md)의 결과와 남은 제한을 기록한다. 비교 기능을 넣으면 G12도 적용한다.

### 5 배포 검토

승인된 배포 단계에서 실제 앱 빌드·Workers 자산·주소·운영 원점 CORS를 확인한다. 출시 안내는 검증된 지원 조합·데이터 경로·보안 한계에 맞춰 작성한다. 예상 URL만으로 배포 완료를 표시하지 않는다.

### 6 후속 기능

모델 비교 확대, 로컬 템플릿·백업, 추가 코덱·Safari·모바일을 실제 수요와 검증 결과에 따라 검토한다. 실시간 녹음·협업·계정·동기화·결제·자동 공유는 별도 요청과 범위 결정 전까지 추가하지 않는다.

## 다음 변경 기록의 최소 항목

**2026-10-17 모델 관리 통합 결정:** 사용자는 연결 설정을 모델 관리로 합치고 모델마다 엔드포인트와 키를 등록하는 방향을 선택했다. 전사와 요약·정리 모두 OpenAI·OpenRouter·OpenAI 호환/로컬 모델을 각각 골라 실제 작업에 사용할 수 있어야 한다. 별도 공유 Connection 관리 구조는 두지 않는다. 중복 키 안내는 키 저장 방식 아래에 모으고 제공사별 정책은 해당 모델에만 표시한다. [설계안](superpowers/specs/2026-10-17-unified-model-management-design.md)과 [구현 계획](superpowers/plans/2026-10-17-unified-model-management.md)을 작성했다. 스키마·이전·초기 로컬 주소 범위 등 기술 세부는 제안이며 구현·실제 유료 요청·커밋·배포를 실행한 기록이 아니다.

**2026-10-17 음성 메모 개념·설정 통합 후속 결정:** 사용자는 아이콘을 앱에 준비된 목록에서 골라 추가하도록 확정했다. 기본 9개는 유지하고 추가·제외·복원한 선택지를 암호화 저장한다. 별도 `음성 준비` 설정 탭을 없애고 기존 `화면 · 언어` 탭의 테마·UI 언어 아래에 아이콘·색상·사용 언어와 JSON·프롬프트를 모은다. 앱이 제공하는 화면 문구의 `회의`는 `음성 메모`, 생성 결과의 `회의록`은 `정리 노트`, 단계명은 `메모 정리`로 바꾼다. 영어도 Voice memos/Notes로 맞춘다. 사용자가 저장한 제목·본문과 내부 데이터 식별자는 다시 쓰지 않는다. 이전 설정 파일을 가져올 때 현재 아이콘 목록은 유지한다. [변경·검증 기록](superpowers/evidence/2026-10-17-memo-appearance/README.md)을 따른다.

**2026-10-17 음성 준비 적용 대상·배포 결정:** 최신 첨부 화면과 설명에 따라 회사 색은 메모 제목 앞 아이콘의 색상 선택지로 관리한다. 기존 테마·화면 언어 선택을 유지한다. 기본 아이콘 9개는 준비 화면에서 고르고 설정에 세트를 보여준다. 사용 언어는 표시 이름·코드 쌍을 관리해 준비 화면의 복수 선택에 반영한다. 탭은 `음성 준비`, 링크는 `색상 · 언어 목록 관리 →`로 명확히 한다. JSON·AI 안내는 색상·입력 언어 두 목록만 포함한다. 사용자가 이전 로컬 전용 결정을 변경해 커밋·배포를 직접 요청했다. [후속 검증·배포 기록](superpowers/evidence/2026-10-17-selection-lists/README.md)을 따른다.

결정 날짜, 변경한 요구·제안·질문 ID, 선택 이유와 버린 대안, 근거 실험, 영향받는 화면·데이터·출시 조건을 남긴다. 새 정보가 과거 주장을 바꾸면 관련 문서를 함께 갱신하고 실험의 당시 조건 자체는 보존한다.


**2026-10-17 구현 중 키 분리 결정:** 키는 이름·origin·저장 방식·버전을 가진 별도 credential로 저장하고 모델에는 선택 참조만 연결한다. 같은 서버의 키를 여러 전사·정리 모델에서 재사용하고 인증 없는 로컬 서버는 참조 없이 실행한다. 모델 JSON은 키와 참조를 모두 제외한다. 키 교체·저장 방식 변경은 연결 모델에 함께 적용하고 모델 연결 해제와 키 삭제를 구분한다. 모델 관리 내부에서 처리하며 별도 연결 탭은 만들지 않는다. [로컬 구현·검증 기록](superpowers/evidence/2026-10-17-unified-model-management/README.md).

**2026-10-17 API 키 독립 관리 후속 결정:** 사용자는 첨부한 목록 화면을 바탕으로 API 키 관리를 모델 관리에서 분리하고, 필요한 정보만 두며 키를 먼저 저장한 뒤 모델은 나중에 등록하는 설계의 구현을 승인했다. 설정에 `API 키` 탭을 추가한다. 키 목록은 이름·제공사·수정/삭제만 표시하며 연결 모델·사용량·만료·한도는 추가하지 않는다. OpenAI·OpenRouter는 허용 origin을 자동 지정하고 기타 서버는 주소를 입력한다. 모델은 같은 origin의 저장된 키 ID를 선택하고 비밀값·역방향 모델 목록을 중복 저장하지 않는다. 기존 암호화·잠금·키 교체·삭제의 저장 계약을 재사용한다. 이전의 모델 내부 키 입력과 접힌 키 관리 배치는 이 최신 결정으로 대체한다. 이번 승인은 로컬 구현 범위이며 푸시·배포·실제 자격 증명 사용은 포함하지 않는다. [구현·검증 기록](superpowers/evidence/2026-10-17-api-keys/README.md).

**2026-10-17 API 키 보조 카드·모달 후속 결정:** 사용자는 `보관함 잠금` 카드와 같은 보조 영역을 모델 관리 오른쪽에 두고, 키 입력은 모달로 처리하는 구성을 승인했다. 모델 목록은 `STT / LLM`으로 나누고 짧은 설명을 붙인다. 별도 API 키 탭은 제거하되 키의 독립 저장·공유 참조 계약은 유지한다. 인증 없는 로컬 모델에는 키가 필요하지 않다. 키 추가 중 모델 초안을 유지하고 저장 직후 선택할 수 있어야 한다. 모달 취소·Escape는 미저장 키를 지우고 초점을 돌려주며 잠금 시 민감한 입력을 제거한다. 좁은 화면에서는 키 카드가 모델 카드 아래로 이동한다. 사용자가 선택한 `간결한 푸터` 안에 라이선스·소스/재빌드 링크를 유지한다. 앞선 독립 탭·큰 라이선스 카드 배치는 이 결정으로 대체한다. 로컬 구현·커밋 범위이며 푸시·배포·실제 자격 증명 사용은 포함하지 않는다. [구현·검증 기록](superpowers/evidence/2026-10-17-model-settings-layout/README.md).

**2026-10-17 통합 모델 목록·독립 테스트 후속 결정:** 사용자는 STT·LLM을 합친 목록을 기본으로 보고 `전체 / STT / LLM`으로 필터링하는 제안을 승인했다. 각 행에는 테스트·수정·삭제를 구분하고, 수정과 실제 모델 테스트를 별도 모달로 연다. 기본 모델은 단계별로 유지한다. 모델 삭제는 해당 등록과 기본 선택만 제거하고 공유 키·기존 음성 메모·실행 결과는 유지하며 다른 모델을 자동 선택하지 않는다. 키 카드에는 모델 없이 가능한 읽기 전용 인증 확인을 둔다. OpenAI/OpenRouter의 기존 인증 조회 경로를 사용하고, 사용자 지정 서버는 확인 불가로 표시하며 임의 경로로 키를 보내지 않는다. 인증 확인 결과는 세션에서만 유지하고 키 변경·잠금 시 지운다. STT는 짧은 실제 음성 선택, LLM은 편집 가능한 합성 예문으로 시작하고 추가 옵션·요청 전문은 접는다. 전송·공유 안내는 삼각형 펼침 대신 정보 버튼과 안내 모달로 바꾼다. 이번 승인은 로컬 구현·커밋이며 실제 키 사용·푸시·배포를 포함하지 않는다. [변경·검증 기록](superpowers/evidence/2026-10-17-model-list-actions/README.md).
