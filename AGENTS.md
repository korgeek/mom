## Product constraints

- Target a desktop-browser React/Vite/TypeScript app hosted on Cloudflare. Prepare/split/compress audio and manage state in the frontend. Use the user's own provider keys and direct browser-to-provider requests. Do not add MoM accounts, application server storage, an AI proxy/relay, telemetry containing meeting data, or automatic sharing without a new user decision.
- Offer 10/15 **minute** chunks and 10/15 **second** overlap as shown in the reference. Validate actual encoded bytes and supported format/model combinations; estimates alone cannot prove an upload fits. Bound memory for long recordings rather than decoding the entire recording into a retained PCM buffer by default.
- Preserve raw STT responses, source-time mappings, completed results and distinct edited transcript/minutes versions. Resolve overlap without silently discarding uncertain speech. Reuse the selected transcript when output language, sections or text model changes; do not rerun STT for those changes.
- Accept multiple expected input languages and independently selected minutes language/sections. Do not restrict the product to the sample's language list, invent speakers/owners/deadlines, or treat chunk summaries as the final meeting conclusion. Final output is Markdown, editable, downloadable as `.md`, and copyable to the clipboard (latest user requirement). Copy format/button placement remain proposals documented in the review.
- Actually encrypt persisted sensitive audio, transcripts, minutes, metadata and provider keys. **User decision:** encrypted browser persistence is the default for API keys; the sample's session-only option remains an alternative. Never persist plaintext keys or place secrets in source, bundles, URLs, logs, analytics, exports or clipboard output.
- **User decision:** on lock, encrypt/save completed work and stop new work. Remove sensitive content from DOM/accessibility trees, release decrypted data/key references and stop playback. Specify safe handling of in-flight requests, late responses, save failure and other tabs before implementation; do not claim full memory zeroization or that cancelling a request reverses provider charges. Blur alone is insufficient.
- Encryption algorithms/KDF parameters, PIN strength, recovery and key-change details require a reviewed technical design; the prototype's fixed PIN and AES/PBKDF2 labels are not a security implementation. Explain external audio/transcript transmission and provider retention separately from local encryption. Exported/copied text is plaintext outside the vault.
- Implement real functionality. Do not substitute timers, random percentages, fixed transcripts, canned minutes, unconditional connection success or fabricated usage/costs for real processing. Any deliberate demo fixture must be isolated and plainly identified.
